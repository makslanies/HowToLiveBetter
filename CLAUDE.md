# Руководство по жизни с высокой отдачей · правила работы

Это русская версия китайской книги «高性价比人生指南» (оригинал: https://github.com/eternity4719/HowToLiveBetter). Репозиторий: https://github.com/makslanies/HowToLiveBetter. Сайт: https://makslanies.github.io/HowToLiveBetter/. Автор русской версии: Максим Ланиес.

Правила ниже обязательны для любой работы в этом репозитории. Прочитайте их целиком перед правкой. Правила китайского оригинала (формат пункта, уровни доказательств, расчёт выгоды) лежат в его CLAUDE.md. Здесь они сжаты до того, что нужно русской версии. Прежний полный текст этого файла остался в истории git (коммит `40677eb`).

## Главные принципы

1. **Китайское и российское не смешиваются.** Книга описывает Китай: законы, выплаты, цены, телефоны там китайские. Российские сведения живут в отдельных полях «(Россия)» со своими источниками. Нельзя переносить китайскую норму на Россию и нельзя писать «в России так же», если этого нет в российском источнике.
2. **Ничего не выдумывать.** Каждый российский факт стоит на дословной цитате с официальной страницы. Каждое число в тексте есть в цитате. Нет цитаты, нет факта. Короткий честный текст лучше длинного с догадкой.
3. **Честно показывать пробелы.** Если российский текст не написан, на пункте стоит метка, а не молчание (см. «Метки»).
4. **Тест перед завершением.** После любой правки в `tools/ru`, `ru/` или состоянии `ru-work` запустите тесты (см. «Сборка и проверки»). Работа без прохода тестов не завершена.

- `ru/scope.json`: тип каждого пункта (`c` китайский, `m` смешанный, `u` не зависит от страны, `r` российский материал), пояснение и метка аналога.

## Формат пункта

Заголовок `### N. Действие, начинающееся с глагола`, сразу под ним комментарий с меткой стоимости, затем поля:

```
### 1. Пристёгивайтесь ремнём безопасности
<!-- 成本标签: 钱=0 时间=少 毅力=否 收益=大 口径=死亡率 -->
- Затраты: ...
- Простыми словами: ...
- Выгода: ...
- Уровень доказательств: A
- Источники: ...
- Примечания: ...
```

Для китайского пункта российские сведения добавляются полями `- Простыми словами (Россия):`, `- Затраты (Россия):`, `- Выгода (Россия):`, `- Примечания (Россия):`, `- Источники (Россия): название. Проверено ДД.ММ.ГГГГ. <ссылка>`. Строка `- Цена в России` и `- Источники цен (Россия)` относятся к российским ценам. Старый формат `- В России:` остался у нескольких пунктов, новых не создаём.

**Метка стоимости** хранится китайскими символами как данные для фильтров, значения не переводить: деньги `钱` = `0` | `少` | `多`; время `时间` = `少` | `中` | `多`; усилие `毅力` = `否` | `些` | `是`; выгода `收益` = `大` | `中` | `小`; единица счёта `口径` = `死亡率` | `金钱` | `时间` | `自由`. Пороги выгоды: для денег тысячи рублей и больше большая, сотни и тысячи средняя, десятки малая; для свободы уголовная ответственность большая, административная средняя, гражданская малая; для здоровья смотрят снижение риска; для времени часы в день большая, часы в неделю средняя, разово малая. Разные единицы счёта между собой не сравниваются.

**Уровни доказательств:** A число из метаанализа, большого когортного исследования или РКИ, либо закон, приказ или клинические рекомендации с точным текстом; B исследование или официальное разъяснение, число трудно проверить или оно из единственного источника; C опыт или общий совет без прямого источника. Спорные пункты уровня A или B обязаны начинаться примечанием со слова «Спорно» и приводить доводы против.

## Российский слой: как делается

Порядок: **план запросов → пакет доказательств → черновик → проверка → применение → метки → сборка → тесты → коммит и пуш.** Подробности и ограничения лежат в `.claude/skills/ru-layer-pipeline/SKILL.md`.

1. **План и пакет.** `node tools/ru/plangen.mjs` и `plangen2.mjs` составляют запросы по пунктам. `node tools/ru/evidence.mjs [--plans файл] [--redo] --max N` ищет только на официальных сайтах через срезAI (поиск по одному домену, затем общий) и сохраняет выдержки страниц в `ru-work/evidence/<раздел>-<пункт>.md`. Квота срезAI дневная: журнал `ru-work/research/usage.json`, сервер ответом 429 ставит блок до сброса. `node tools/ru/deepen.mjs <пункт> "слово|слово"` докачивает нужные абзацы страниц напрямую, без квоты.
2. **Черновик.** `node tools/ru/freedraft.mjs <ключи> --provider codex|agy|kilo --out ru-work/evidence/drafts-N.json`. Модель выбирает номера предложений из пакета, цитаты подставляет скрипт. Результат сохраняется после каждого пункта, запуск можно продолжать.
3. **Проверка без модели.** `node tools/ru/draft.mjs <файл>`: каждая цитата дословно на странице, каждое число из полей есть в цитатах, адрес есть в пакете. Прошедшая механическую проверку карточка ещё не годная. Её нужно прочитать целиком: отбрасывайте тексты «в источниках не указано», узкие региональные данные, страницы не по теме и утверждения, которых нет в цитатах.
4. **Применение.** `node tools/ru/draft.mjs <файл> --apply`, затем `node tools/ru/apply-overlay.mjs`. Применяйте только проверенные ключи (соберите отдельный файл `drafts-NNN.json`).
5. **Метки и ссылки.** `node tools/ru/analog.mjs` пересчитывает метки аналога, `node tools/ru/materials.mjs` блок «Российские материалы по теме», `node tools/ru/library.mjs` «Российскую библиотеку». Все три пишут в закоммиченные `ru/*.json`, потому что сервер `ru-work` не видит.

### Метки у пунктов без российского слоя

- `a: 'none'` «Российского аналога нет». Ставится только когда пункт описывает порядок, существующий только в Китае, и после ручной проверки. Пометку ИИ «аналога нет» вручную не принимаем за истину (так были сняты четыре пункта).
- `a: 'searched'` «Искали в официальных российских источниках, прямого аналога не нашли. Это не значит, что его нет». Ставится, если пакет собран, а подходящего текста нет.
- Без метки: «Российские правила пока не проверены».

Никогда не пишите «аналога нет» про пункт, который только искали.

### Раздел 35 «Российские справки»

Самостоятельные российские карточки без китайского оригинала, тип `r` в `ru/scope.json`. Данные пишутся в `ru-work/cards/cards.json` (образец: r-001…r-003), собирает и проверяет `node tools/ru/cards.mjs`: сайт только официальный, цитата дословно на странице, числа есть в цитатах. Файл `ru/book/35-rossiyskie-spravki.md` и записи `35-*` в `scope.json` скрипт перезаписывает сам, вручную их не правим. Задание для исполнителя: `ru-work/prompts/russian-cards-run.md`.

## Правила текста

- Простой русский язык для взрослого без подготовки. Одно предложение, одна мысль, до 30 слов, у каждого предложения подлежащее. Без «следует», «осуществляется», «в рамках», «посредством».
- Не писать оборотами ИИ: «стоит отметить», «важно понимать», «в конечном итоге», итоговой морали в конце абзаца, вступлений вроде «этот пункт про…».
- «Простыми словами»: 2–4 коротких предложения, только то, что есть в «Выгоде». Не добавлять фактов и чисел, которых там нет.
- Не удалять и не менять числа, интервалы и годы в «Выгоде» китайских пунктов. Можно только добавлять перевод в простые слова.
- Суммы без разделителей тысяч. Шестизначные и больше: «около 1 млн рублей (1130040 рублей)».
- Без восклицательных знаков, без поучений, без «Россия:» в начале заголовка карточки.
- Если в российской справке источник говорит про другую тему или регион, не обобщайте: пишите ровно то, что в цитате.

## Источники и цитаты

- Российский слой: только официальные сайты (`*.gov.ru`, `cbr.ru`, `sfr.gov.ru`, `vsrf.ru`, `sledcom.ru`, `mvd.ru`, `gosuslugi.ru`, `trudvsem.ru` и т. п.) и справочные базы закона (`consultant.ru`, `garant.ru`, помечаются «справочная база закона»). СМИ, блоги, агрегаторы и маркетплейсы не источники.
- Китайские пункты: журнальные статьи (DOI или PubMed), официальные отчёты. Не добавлять новые источники без проверки по оригиналу. Выдуманные DOI запрещены.
- Цитата до 40 слов, дословная. Остальное своими словами. Законы и официальные документы можно цитировать, но не копировать страницами.
- Ссылки в поле источников пишутся как `название. Проверено ДД.ММ.ГГГГ. <ссылка>`, несколько через ` ; `.
- Дата проверки обязательна: законы меняются.
- Мёртвые ссылки находит `node tools/check-links.mjs` (на сервере раз в неделю, локально через прокси).

## Сборка и проверки

Основные команды (из корня репозитория):

```
node tools/ru/validate.mjs                 # структура, счётчики, метки: ожидается 0 ошибок
node tools/ru/build-index.mjs              # пересобрать ru/index.html
node tools/ru/readme-root.mjs              # пересчитать корневой README.md
node tools/ru/build.mjs                    # сайт, офлайн-файл, страницы, GEO; занимает несколько минут
node --test tools/ru/country-fields.test.mjs tools/ru/prices.test.mjs   # обязательные тесты
```

- Сборка `build.mjs` долгая. Запускайте её так, чтобы не упереться в тайм-аут команды, и дожидайтесь окончания, прежде чем читать `dist-ru` или запускать тесты (тесты читают `dist-ru/site`).
- Если правите шаблон сайта, правьте `tools/ru/build-index.mjs`, `tools/ru/pages.mjs`, `tools/ru/geo.mjs` или файлы в `tools/ru/spa/`. После правок пересоберите и посмотрите результат: скриншот страницы или проверку в браузере (`Google Chrome --headless --screenshot`).
- Счётчики (число пунктов, уровни A/B/C, покрытие) считаются из текста книги. Не вписывайте их руками: запустите `validate.mjs` и `readme-root.mjs`. В `ru/README.md` две фразы про уровни и выгодность содержат числа и пересчитываются при добавлении пунктов.
- Метки `scope.json` для раздела 35 и метки аналога зашиты в закоммиченные файлы. После партии новых пунктов запускайте `analog.mjs`, `materials.mjs`, `library.mjs`.

## Секреты и доступы

- Ключи лежат в `.env` (в `.gitignore`): `SREZAI_API_KEY`, `SREZAI_BASE_URL`, `OPENAI_API_KEY` (не используется, у владельца OpenAI-ключ не работает), `2INDEX_*`, `YANDEX_METRIKA_*`. Сервисный аккаунт Google лежит в `commanding-way-*.json` (тоже в `.gitignore`).
- **Никогда не печатайте значения ключей и не выполняйте `source .env`**: интерпретатор принимает строки за команды и выводит их куски. Читайте `.env` скриптом (разбор `KEY=value`) и печатайте только имена и длину.
- `YANDEX_METRIKA_ID` это идентификатор OAuth-приложения, а не номер счётчика. Номер счётчика 113465970.
- Отправляйте во внешние сервисы только публичный текст: страницы книги и выдержки с официальных сайтов. Бесплатные шлюзы могут логировать запросы.
- Что-либо внешне видимое (посты в соцсетях, письма, публикация в чужие сервисы, сообщения в GitHub-ленту) делается только после согласия владельца.

## Исполнители и квоты

- **срезAI** (поиск и чтение страниц): дневной лимит. `evidence.mjs` ведёт журнал `ru-work/research/usage.json` и останавливается при ответе 429. Не запускайте тяжёлый сбор, пока не сбросилась квота, и не обходите блок.
- **Codex CLI** (`codex exec -s read-only` для черновиков): пишет тексты через вход в ChatGPT. Может упереться в лимит, тогда запрос повисает: остановите процессы (`pkill -f "codex exec"`) и подождите сброса.
- **agy** (Antigravity, Gemini): может быть исчерпана недельная квота. **Kilo** (бесплатный шлюз): качество ниже, обязательна ручная вычитка.
- **OpenAI API недоступен.** Скрипты `translate.mjs`, `research.mjs`, `prices.mjs` с моделями OpenAI не запускать.
- Долгие запуски (больше пары минут) ставьте в фон и сохраняйте результат после каждого элемента, чтобы остановка ничего не потеряла.

## Как отвечать пользователю

- По-русски, по делу, без восклицательных знаков. Сначала результат, потом детали.
- Говорить прямо, что сделано, что не сделано и что проверено. Не сообщать «готово», пока не прошли сборка, валидатор и тесты. Если что-то не проверено в браузере, так и написать.
- Предлагать следующий шаг одной фразой, если он есть. Не спрашивать разрешение на то, что уже согласовано.
